# 10 语言内核视角与算法基本功

## 先说结论

精通层的两块底层修养：

1. **语言内核视角**：运算符、类型转换、值与引用、作用域与内存——这些「语言怎么实现我写的代码」的知识，决定你能不能在诡异 bug 面前不慌。
2. **算法基本功**：网站按 LeetCode Hot 100 选了六个典型题五语言对照。转全栈不需要刷三百题，但需要「拿到一个数据处理问题，知道它属于哪个模式」。

## 内核四题

**类型转换与相等判断**。JS 的 `==` 陷阱你是过来人（`"1" == 1` 为 true），Python 的 `1 == True` 也是 true，Java 的 `Integer` 缓存池 `-128~127` 会让 `==` 在小数字上碰巧正确——这是面试陷阱更是线上事故源（超出缓存范围就变 false）。Go 和 Rust 压根没有隐式数值转换，类型不对就是编译错误。五门语言的规则网站「类型转换与相等判断」主题有完整对照，建议只记一条元规则：**隐式转换越多的语言，越要主动写显式比较**。

**值与引用、深浅拷贝**。第 03 篇提过，这里给结论表：

| 语言 | 默认行为 | 坑位 |
|------|---------|------|
| Python/JS | 对象/数组按引用 | 函数里改了入参，调用方跟着变 |
| Java | 原始类型值，对象引用 | 方法内 `list.add()` 影响调用方 |
| Go | 一切赋值是拷贝，但 slice/map 底层含指针 | 「拷贝了怎么还是变了」 |
| Rust | 所有权转移（move） | 想保留原值必须显式 `clone()` |

**作用域与内存管理**。Python/JS/Go/Java 有 GC，你不用想释放；Rust 编译期确定每块内存的死期（所有权 + 借用检查器），没有 GC 停顿。代价是新手期和借用检查器搏斗，收益是运行时性能可预测——这就是 Rust 版实验室代码比 Python 版长几倍的来源：多出来的行不是啰嗦，是把 JS 运行时帮你做的事搬到了你眼前。

**运算符**。五语言的 `/` 行为不同值得单独记：Python 的 `/` 永远得浮点（`10/3 = 3.33`），整除是 `//`；JS 只有 `/`（全浮点）；Java/Go/Rust 的整数 `/` 直接截断（`10/3 = 3`）。后端算金额时差一个整除语义就是资损事故，这也是为什么金额永远用整数最小单位（分）或 Decimal 类型，不用浮点——网站综合案例「电商订单：状态机 + 金额计算」（`c11-capstone-a.ts`）整章就在演示这件事。

## 算法：六个 Hot 100 题的真正用法

网站 `c14-algorithms.ts` 选了六个题：两数之和（哈希表）、二分查找、反转链表、最大子数组和（动态规划入门）、有效括号（栈）、爬楼梯（DP 最小样本），外加冒泡与快排。

转全栈视角下，这六个题的正确打开方式不是背解法，而是认出**它们各自代表的模式在后端代码里的化身**：

| 题目 | 模式 | 后端化身 |
|------|------|---------|
| 两数之和 | 空间换时间，哈希表 | 「这个 id 存在吗」的一切判断（你每天在写） |
| 二分查找 | 有序数据折半 | 分页定位、时间范围切片 |
| 反转链表 | 指针操作 | 树/图遍历的基本功（组织架构树、菜单树） |
| 最大子数组和 | 动态规划 | 「前 i 个的最优解依赖前 i-1 个」的一切问题 |
| 有效括号 | 栈 | 括号匹配、撤销栈、表达式解析 |
| 爬楼梯 | 递推 → 记忆化 | 网站「记忆化缓存（Memoize）」主题的算法原型 |

举一个直接的后端例子：树形结构的菜单/评论/组织架构处理，就是「反转链表」练的指针功夫 + 递归的合成。网站「常用处理逻辑」章的「树形结构递归处理」（`c13-common-logic.ts`）有五语言完整实现，那个主题比第六道算法题离你的日常近得多。

**学习路径建议**：先用你最熟的语言把六题写一遍（LeetCode 直接提交），然后到网站上读同一个题的另两门语言实现——重点看 Rust 版，感受「无 GC 语言表达同一算法」的差异（链表题尤其明显：Rust 里 `Option<Rc<RefCell<ListNode>>>` 会颠覆你对链表的认知）。

## 综合案例：把修养拼成作品

语法路径的终点是两个综合案例，它们是前面所有知识的会考场：

- **电商订单：状态机 + 金额计算**（`c11-capstone-a.ts`）：状态机（pending → paid → shipped → done，非法流转要拒绝）+ 金额计算（整数分/Decimal）+ 类型建模（枚举、模式匹配）。五语言对照里最值得精读的是 Rust 的 match 表达式和 Java 的 enum——同一个状态机，两种「让非法状态不可表示」的哲学。
- **泛型 LRU 缓存**（第 03 篇提过）：哈希表 + 双向链表 + 泛型 + 容量控制。写完它，你对「数据结构选型决定性能」会有体感：GET/PUT 都是 O(1)，靠的就是哈希表 O(1) 定位 + 链表 O(1) 挪位。

这两个案例的难度标注（difficulty 1-5）在网站上有显示，作为自测：不看提示写完 LRU，语法路径就算毕业了。

## 常用处理逻辑：日常后端的真题目

`c13-common-logic.ts` 的四个主题是比算法题更高频的日常：去重与分组统计、重试与指数退避、树形递归、记忆化缓存。这四个的实现难度都不高，但每个都是「面试考算法、工作考这个」的典型。如果你时间有限，**优先练这四个而不是多刷十道 Hot 100**。

## 练习

1. LeetCode 提交六个 Hot 100 题（任选语言），再到网站对照读两门不熟语言的实现。
2. 用两门语言实现「树形结构递归处理」（扁平列表 ↔ 树互转），这是前后端交接数据时真实出现的形状。
3. 写电商订单状态机（任选语言）：非法流转（如 done → paid）必须抛错，金额用整数分。写完对照网站综合案例版本。
4. 给 LRU 加上第 03 篇讲的泛型和第 08 篇讲的过期时间——一个小缓存库就成型了。
